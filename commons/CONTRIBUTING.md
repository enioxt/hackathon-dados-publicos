# Como contribuir

## Antes de começar

Confirme que você tem direito de compartilhar o material. Escolha um único problema e
escreva o critério verificável que encerrará o trabalho. Sem aceite objetivo, a issue ainda
é conversa, não bounty.

## Fluxo mínimo

1. Abra uma issue pelo formulário adequado.
2. Marque o estágio: `CONCEPT`, `PROTOTYPE` ou `REAL`.
3. Declare fontes e limites conhecidos.
4. Se houver código, inclua teste ou demonstração reproduzível.
5. Abra um pull request ligado à issue.
6. A revisão confere autoria, licença, segurança, dados e aceite.

## Contribuições reconhecidas

Código, pesquisa, documentação, UX, teste, triagem, dados públicos e manutenção contam.
O histórico registra quem propôs, implementou, revisou, financiou e testou.

## Remuneração

Código aberto não cria pagamento automático. Uma contribuição remunerada só existe quando
uma issue declara previamente: contratante, valor, escopo, critério de aceite, responsável
pela validação e forma de pagamento. Serviço contratado e licença do código são camadas
separadas.

## Segurança e privacidade

Não envie segredos nem dados pessoais. Use dados públicos, sintéticos ou anonimizados de
forma comprovada. Achado sensível deve ser comunicado privadamente ao responsável, nunca
aberto numa issue pública.
